# 编号 1–25 开发规范与协作约定

版本：2026-11-20。适用分工：本分支负责原表 A 列编号 1–25，同事负责 26–51。本规范先约定开发与合并，不代表批量页面已经实现，也不代表同事分支已经采纳。

## 一、目标与范围

以用户提供的后评估 Excel 和其中的新版界面截图复现前端。每个编号具有可直接访问、可从业务菜单进入的最小可运行入口，入口可以复用同一业务列表及对应弹窗，不为“新增/修改/查询”机械复制整套列表。禁止以索引页、空白占位或纯提示替代验收页面。

范围以原表 A 列编号为准，不按筛选后的行号重新编号。原表 1–25 的 C 列均为“自助取数”，D 列分为五组：取数任务（1–3）、系统适配（4–12）、数据下载（13–14）、文件上传模块优化升级（15–17）、模型全局视图（18–25）。排除“报表数据”不能自动把其他分类全部纳入本分支；经分应用、报表管理、系统传输安全、短彩信通报不在本次 1–25 范围。

同事材料标题为 26–51，正文“1–25、25个功能点”是分工笔误，应以 26–51、26 个功能点理解。不可据此开发重叠编号。

## 二、素材与证据

源文件：中国移动江西公司2024年大数据产品扩容项目数据直通车子项目委托开发合同后评估材料_梳理_前台_报表_后评估(1)_已处理(2).xlsx，当前位于本机桌面，约 304.6 MB。同事使用的是后缀 (3) 版本，不可假定图片 ID、media 文件名和内容完全相同。双方用“原编号 + 功能名称 + 源版本 + 单元格 + DISPIMG ID”对齐证据。

只读 ZIP/XML 提取，不用 openpyxl.load_workbook 全量加载，不修改源 Excel。文字读取 xl/sharedStrings.xml；工作表由 xl/workbook.xml 和关联文件定位。当前清单来自 Sheet!A2:AD26：A 编号、C 二级功能、D 三级功能、E 四级功能、Z:AD 证明材料。当前 1–25 图片公式在 Z:AC，AD 也应检查。不能仅凭 N+1 推算所有版本行号，须核对 A 列值。

图片映射：xl/cellimages.xml 的 xdr:pic/cNvPr/@name 为 DISPIMG ID，a:blip/@r:embed 通过 xl/_rels/cellimages.xml.rels 解析到 xl/media。xdr 命名空间为 http://schemas.openxmlformats.org/drawingml/2006/spreadsheetDrawing。只解压本功能需要的图片到临时目录，记录原尺寸。空共享公式需容错，不把公式缓存错误当业务文案。

截图中的标题、字段、数据、菜单面包屑是页面验收依据；Excel C/D/E 列是任务分类，不能直接作为导航。标注用红框不作为产品元素。多图分别登记主列表、查询场景、弹窗、成功状态，不挑一张省略其余状态。缺图或文字冲突记录待确认，不凭空声称已还原。

## 三、统一技术与功能边界

沿用 Vue 3、Vite、Element Plus、Vue Router 和现有 AppLayout。侧栏 159px、顶栏 51px、Logo、版权和既有页面外壳保持一致。不得另建应用或引入另一套 UI 库。

新增页面仅使用本地静态数据及 ref/reactive 内存状态，不新增 API、不连接数据库、不修改 server。现有即时取数浏览依赖 mock API 的行为保留。刷新页面恢复种子数据；不默认接入 localStorage。

只模拟截图中需要的操作：查询/重置、选择、分页、详情、弹窗表单、内存新增修改删除与提示。查询草稿与已应用条件分开，点查询或回车才更新结果，重置恢复默认。删除/派发等有确认的截图保留确认，取消不改变数据。分页、统计、选择须随结果更新，避免跨场景残留选择。

不做真实 SQL 执行、权限赋权、审批、消息通知、证书加密、后台取数或服务端文件读写。文件上传只模拟名称/状态/拆分预览，不上传或读取真实内容。导出仅在页面需要时生成当前模拟数据的浏览器 CSV/Blob；现有 CSV 功能保留，不引入后端落盘。模拟操作要明确提示，不能冒充真实业务完成。

编号 6 的即时任务查询延用现有两种固定场景：吉市场口大数据分析表、终端质量监控日报表，各 5 条，进度 100/100/65/0/40；其他名称为空结果。未经新需求不扩充真实查询能力。

## 四、目录、路由及注册契约

双方目标统一目录：

```text
src/views/newFeatures/
  registry.js                 # 公共聚合入口，由整合方维护
  registry-01-25.js            # 本分支功能元数据、懒加载映射、面包屑
  registry-26-51.js            # 同事功能映射（待双方接入）
  FeatureHost.vue             # 公共编号宿主
  IndexPage.vue               # 公共进度索引，只是辅助入口
  XxxYyy.vue                  # PascalCase 业务页面，避免两人同名
src/styles/new-feature.css    # 公共 nf- 样式
src/config/menus.js           # 公共业务菜单树
```

统一访问地址 `/new/1` 至 `/new/51`，不是 `/new1`。只维护一个 `/new/:no` 动态路由。保留 `/query/instant`、`/query/tasks` 旧地址有效；编号 6 接入时复用 InstantTaskQuery.vue 或路由适配，不再新写一份相同数据页。

每个分段注册文件建议导出 featureViews（编号到懒加载函数）、featureBreadcrumbs（编号到菜单路径）、featureMeta（编号、原表名称、素材索引、状态）。公共 registry.js 仅合并导出，同事现有 registry.js 的字段先核实再适配，禁止直接覆盖。编号键不得重复，未知编号显示明确的未找到状态；未实现入口不得标为已验收。

新增代码优先放本分支页面及 registry-01-25.js。不要为了单页改 src/main.js、package.json、锁文件、路由守卫、AppLayout、TopBar 或全局 CSS。

**当前事实**：本分支目前没有 newFeatures/、registry.js、FeatureHost.vue、IndexPage.vue、new-feature.css，也没有同事描述的浮层菜单或 app-content-plain 自动切换。这些是待整合的公共基础，不是已完成能力。本次仅制定规范，不创建或迁移这些业务基础设施。批量开发前先整合双方已存在的实现，再一次性补齐公共入口。

## 五、导航与面包屑必须一致

菜单按截图业务路径挂载，有 children 的节点只展开，叶子用 route 跳转。每个 key 全项目唯一，建议 `nf-编号-用途`；相同父节点按 key 合并，禁止两份“自助取数”或“业务数据管理”。末级标签与面包屑文字一致，当前页自动展开、选中；刷新和直接访问同样生效。

编号 6 当前确定路径为“自助取数 / 取数任务 / 即时任务查询展示”，不能因 Excel D 列是“系统适配”而改回去。其余编号实现前逐图登记真实路径，未读图的路径标待核对。编号 25 与同事 26–28 可能共用模型历史版本管理界面，须复用公共业务容器/数据结构，不能相互覆盖页面。

统一采用通用菜单树，禁止为每个一级菜单复制专用判断。当前 SideNav 的 tasksExpanded 与三级渲染是既有实现；同事的右侧浮层方案到位后优先整合一套通用浮层，避免 159px 内长文字折行。浮层实现前不得在规范中写“已封装”。菜单点击、关闭、收起、选中和溢出展示须统一。

面包屑由注册元数据提供给顶栏，禁止页面内部再手写一套。当前 /query/* 的 meta 保留；批量入口接入后以对应注册信息为唯一来源。

## 七、逐功能验收流程（强制执行）

### 7.0 用户验收批次（最新约定）

开发者自行逐项执行G1–G7，自验通过后直接继续下一编号，无需用户逐项确认，也不以单项完成为由结束当前工作。每累计完成5个编号才暂停提交用户验收：1–5、6–10、11–15、16–20、21–25。

自验和用户验收分别记录：功能项G1–G7通过标记“自验通过”；批次标记“待用户验收/用户验收通过/需修改”。此前“已验收”仅表示开发者自验，不代表用户已验收。每批提供5项的入口、检查结果、截图证据和实际限制，等用户反馈后修正本批问题；用户确认本批通过后进入下一批。不得把用户未回复视为批准。

每项失败仍须先修复再进入下一项；不降低截图、交互、构建及回归标准。批次内使用简短进度更新继续工作，仅在真实阻塞需要用户信息或该批5项自验全部通过时交回用户。当前第一批1–5：全部自验通过，待用户验收；6–10已逐项自验通过，待本批用户验收。

### 7.1 顺序与放行条件

每次仅允许一个编号处于“开发中/待验收”。按 1→25 顺序推进；此前已存在的编号 6 代码保留，到编号 6 时补做完整验收，不视为提前通过。公共基础设施只实施当前编号必需的部分，不能借此提前开发后续功能。

必须依次完成下述 G1–G7，所有适用检查通过且证据齐全，才将当前编号改为“已验收”并开始下一编号。任意一项失败：留在当前编号，修复后重测受影响检查及回归项。不得以构建通过代替业务或视觉验收，不得带已知缺陷进入下一项，不得在收尾时集中补验。检查不适用时必须写明原因，不能留空或默认通过。

缺少关键截图或无法判定业务结果时，先在现有 Excel、其他截图和只读参考项目中查证；仍无法解决则标记“缺素材待确认”，报告具体缺口并暂停后续功能开发。仅可继续当前项的取材、排查和修复，不自动跳到下一项。流程由开发者自行执行，无需用户逐项批准；只有实际缺失且无法自行确定的信息才请求用户补充。
