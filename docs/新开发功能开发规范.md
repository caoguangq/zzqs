# 新开发功能（编号 26-51）开发规范

> 适用范围：`新开发功能/` 后评估材料中分配给我们的 26 个功能点（编号 26-51）。
> 本文件是给共同开发的同学看的统一格式说明，照着做出来的页面风格才会一致。

## 一、目标

每个功能点做成一个能在浏览器点开的最小可运行页面：

- 一个功能点 = 一个截图里真实的业务界面（编号 26 一个页面、27 一个页面…）
- **页面必须挂在截图面包屑对应的侧栏菜单路径下**，例如编号 26 挂在 `业务数据管理 / 数据模型准备 / 模型历史版本管理`
- 外壳（159px 深色侧栏 + 51px 顶栏）沿用现有 `AppLayout`，**不要改外壳**
- 数据全部写死在页面里（`ref` 数组 + 内存增删），不新增后端接口、不接数据库
- 明确不做：权限校验、文件读写、真实 SQL 执行、审批流、消息推送

## 二、素材获取方法

源文件：`新开发功能/中国移动江西公司2024年…后评估(1)_已处理(3).xlsx`（304MB，**已加入 .gitignore，不要提交**）。

这是 WPS 生成的文件，图片用 `=DISPIMG("ID_xxx",1)` 公式嵌在单元格里。

1. **绝对不要用 `openpyxl.load_workbook()` 打开**，304MB 会直接吃光内存。把它当 zip 读。
2. 文字：`xl/sharedStrings.xml`
3. 图片映射：`xl/cellimages.xml` 里 `<xdr:pic>` 的 `cNvPr/@name` 就是 `DISPIMG` 的 ID，`@descr` 是图片说明，`a:blip/@r:embed` 经 `xl/_rels/cellimages.xml.rels` 映射到 `xl/media/imageXX.png`
4. 行数据：`xl/worksheets/sheet1.xml`，**编号 N 对应行号 N+1**；A 列编号、E 列功能点名称、Z/AA/AB/AC 列是截图
5. 只把需要的图从 zip 里 `read()` 出来写到临时目录，再用看图工具打开

> 命名空间陷阱：`xdr:pic` 用的是 `drawingml/2006/spreadsheetDrawing`，**不是** `drawingml/2006/picture`，写错会解析出 0 张图。

新增一个功能点的标准流程：

1. 在 `src/views/newFeatures/` 新建 `XxxYyy.vue`，类名只用 `nf-` 前缀，只写这一页特有的样式
2. 到 `registry.js` 登记两处：

```js
const featureViews = { 27: () => import('./ModelHistoryVersion.vue') }
const featureBreadcrumbs = { 27: ['业务数据管理', '数据模型准备', '模型历史版本管理'] }
```

3. 到 `src/config/menus.js` 把页面挂到对应菜单路径下（见第五节）
4. 路由不用改，`/new/:no` 会自动加载

## 五、菜单挂载规则

侧栏菜单是三级结构，在 `src/config/menus.js` 里配置：

```js
{
  key: 'data', label: '业务数据管理', icon: 'briefcase',
  children: [
    {
      key: 'data-model-prepare', label: '数据模型准备',
      children: [
        { key: 'data-model-history', label: '模型历史版本管理', route: '/new/26' }
      ]
    }
  ]
}
```

- 有 `children` 的菜单**点击只展开、不跳转**；最末级菜单用 `route` 跳转
- 侧栏只有 159px，放不下长菜单名，二级/三级用**右侧浮层**展示（悬停或点击打开），已封装在 `SideNav.vue`
- 页面面包屑写在 `registry.js` 的 `featureBreadcrumbs`，由路由守卫自动写入顶栏，**必须和截图里的面包屑一字不差**
- 同一个业务页面的多个功能点（如 26 新增 / 27 修改 / 28 删除）共用一个菜单入口，各功能点页面用 `/new/26`、`/new/27`、`/new/28` 区分，面包屑相同

## 七、验收流程（硬性）

**做完一个功能点，必须和素材截图逐项比对通过，才能开始下一个。**

1. 按参考图尺寸截图（编号 26 的图是 1672×941）：

```bash
npx playwright screenshot --channel msedge --viewport-size=1672,941 --wait-for-timeout=2500 http://localhost:5173/new/26 out.png
```

2. 和素材图拼成上下对比图，逐项核对：

| 检查项 | 标准 |
| --- | --- |
| 菜单路径 | 能从侧栏进入，面包屑三节文字与截图一致 |
| 标题 | 卡片标题、页面标题逐字一致 |
| 筛选项 | 标签、顺序、控件类型（下拉/输入/单选）一致 |
| 表格 | 列名、列顺序、列宽比例、对齐方式一致 |
| 数据 | 行数、每行文案、顺序一致；异常日期照抄，不许「修正」 |
| 按钮 | 文案、位置、主次样式一致 |
| 弹窗 | 标题、字段、必填星号、按钮一致 |
| 交互 | 截图里出现的操作都能点通，控制台 0 报错 |
| 构建 | `npm run build` 通过 |

3. 全过 → 在 `CLAUDE.md` 进度表把该项改为「✅ 已验收」；有一项不过 → 改到过为止，**不做下一个**。

## 八、踩过的坑

- `openpyxl` 打不开 304MB 的文件，必须当 zip 读
- 同一功能点的多张截图**可能不是同一个页面**（26 的三张里两张是「模型历史版本管理」，一张是「模型历史版本查询」）→ 以最完整的那张为主界面，弹窗和提示从其他张取
- 参考图内容区是**白底**，不是 `#f5f6fa`；表格相对卡片还有 24px 内缩
- 表格文字用 `word-break: normal; overflow-wrap: break-word`，用 `break-all` 会把 `20260311150738` 这种长数字拆断；时间列要 `nowrap`，否则会折行
- 列宽要按参考图竖线换算成百分比，凭感觉给会把「创建时间」挤成两行
- 侧栏 `overflow` 原来是 `hidden`，浮层子菜单会被裁掉，已改为 `visible`
- 新页面不调接口，改完刷新即可；不需要重启 mock 服务
